# WCAG 2.2 合规模型（Playbook）

> 把"合规"从口号变成可执行的判定标准。本篇解决：该以哪个等级为目标、哪些成功准则（SC）最常踩雷、以及它们与法律的关系。

## 何时用本篇

- 接到"做个无障碍合规"或"达到 AA"的需求，但不知道边界在哪
- 需要向团队/客户解释为什么做某件事（合规依据）
- 制定测试清单、写审计报告时，需要权威 SC 条目

## 四原则 POUR（记忆锚点）

| 原则 | 含义 | 典型失败 |
|------|------|----------|
| **P**erceivable 可感知 | 信息能被任意感官接收 | 图片无 alt、对比度不足、只靠颜色传达状态 |
| **O**perable 可操作 | 所有功能可用键盘/辅助技术完成 | 无法键盘操作、无焦点指示、超时无提示 |
| **U**nderstandable 可理解 | 内容与操作清晰 | 语言未声明、标签误导、输入错误无说明 |
| **R**obust 健壮 | 能被各类辅助技术解析 | 自定义控件缺 role/state、动态更新不播报 |

## 合规等级与目标选择（决策树）

```
问：法律/合同/采购方是否要求？
├─ 是（欧盟公共部门/EAA、美国 ADA/Section 508、政府采购）→ 至少 AA
└─ 否 → 仍默认 AA（行业共识底线），AAA 仅对局部高对比/特定场景追求
```

- **A**：最低门槛，约 30 条 SC，几乎都会顺带满足。
- **AA**：**默认目标**。WCAG 2.2 共 50 条 SC，AA 覆盖绝大多数法律要求。
- **AAA**：仅对特定内容（如认知障碍友好）按需达成，不作为整站强制。

> 经验法则：**以 WCAG 2.2 AA 为整站目标**，把 AAA 中"非文本对比 7:1""字间距"等少数可落地的局部纳入。

## 高频 SC 速查（带 pass/fail 判据）

| SC | 名称 | 判定要点 | 常用工具 |
|----|------|----------|----------|
| 1.1.1 | 非文本内容 | `<img>`/图标按钮有 `alt`；装饰图 `alt=""` | `a11y_audit.py` |
| 1.3.1 | 信息与关系 | 结构用语义标签/正确 roles 表达，不靠视觉 | `aria_lint.py` |
| 1.4.3 | 对比度（最小） | 正文 ≥ 4.5:1，大字 ≥ 3:1 | `contrast_check.py` |
| 1.4.11 | 非文本对比 | UI 组件边界、状态图标 ≥ 3:1 | `contrast_check.py` |
| 2.1.1 | 键盘 | 全部功能可用键盘 | 手动 + 读屏 |
| 2.4.2 | 页面标题 | 每个页面有描述性 `<title>` | `a11y_audit.py` |
| 2.4.6 | 标题与标签 | 标题层级合理、标签描述清晰 | `a11y_audit.py` |
| 3.1.1 | 页面语言 | `<html lang>` 声明 | `a11y_audit.py` |

## 法律语境（一句话定位）

- **欧盟 EAA**（European Accessibility Act，2025-06-28 生效）：面向消费者的数字产品（电商、银行、电子书、交通票务等）强制可达性。
- **美国 ADA / Section 508**：联邦及受资助机构站点必须可达；司法实践常以 WCAG 2.1 AA 为参照。
- **中国 GB/T 37668 / 信息无障碍**：国内标准与 WCAG 对齐，政府采购与公共服务逐步要求。

## 常见失败模式

1. **只盯自动化分数**：Lighthouse 90 分 ≠ 可用。读屏体验、焦点管理不进分数。
2. **对比度用"看起来还行"**：必须算，见 `contrast_check.py`；`#777` on `#fff` 仅 4.48:1，差一口气就 FAIL。
3. **装饰图也写冗长 alt**：装饰图应 `alt=""` 让读屏跳过，而不是 `alt="decorative line"`。
4. **动态提示只视觉**：Toast/错误用 `role="alert"` 或 `aria-live` 播报，否则读屏用户无感知。

## 限制

- 本篇给"判据与依据"，不给逐控件写法——组件级写法见 `semantic-html-aria.md` 与各子技能。
- 具体法条以最新官方文本为准；本篇仅用于技术对齐，不构成法律意见。
