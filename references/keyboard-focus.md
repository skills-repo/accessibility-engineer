# 键盘操作与焦点管理（Playbook）

> 可操作性的地基。解决：所有功能能否不用鼠标完成、焦点可见且有序、模态/路由切换时焦点不丢失。

## 何时用本篇

- 自定义弹窗/抽屉/菜单打开后焦点丢失或关不掉
- Tab 顺序错乱、焦点看不见、能 Tab 进"隐形"元素
- SPA 路由切换后读屏/键盘还停在原页面

## 键盘可达性基线

- **全部功能可用键盘**（SC 2.1.1）。包括打开菜单、提交、关闭、翻页。
- **无键盘陷阱**（SC 2.1.2）：焦点进入某区域后必须能出来（除临时性模态，且提供明确退出方式）。
- **快捷键可关闭/可配置**（SC 2.1.4，仅当你自定义了单键快捷键时）。

## 焦点可见（SC 2.4.7 / 2.4.11）

- 永远不要 `outline: none` 而不给替代指示。
- 推荐：`focus-visible` 提供清晰环；2.4.11 要求焦点指示对比 ≥ 3:1 且足够大。
- 错误做法：`:focus { outline: none }` 又无 `:focus-visible` 兜底 → 键盘用户看不见在哪。

## tabindex 三规则

| 值 | 含义 | 用法 |
|----|------|------|
| 省略 / `0` | 参与自然 Tab 顺序 | 可交互元素默认即可 |
| `-1` | 可经代码 `.focus()` 但不进 Tab 序 | 关闭按钮、SPA 容器、roving 子项 |
| 正数 | 强制提前 | **几乎永远不要**——破坏自然顺序，制造混乱 |

## 焦点管理：三类场景

### 1. 模态弹窗（dialog）
- 打开：`role="dialog"` + `aria-modal="true"`；把焦点移到弹窗内第一个可聚焦元素（或标题）。
- 内部：**焦点陷阱**（Tab/Shift+Tab 在弹窗内循环，不漏到背景）。
- 关闭：焦点**归还**到触发元素；Esc 可关。

### 2. 复合 widget（菜单/标签页/列表框）—— Roving Tabindex
- 容器 `tabindex="0"` 进 Tab 序；子项 `tabindex="-1"`。
- 方向键在子项间移动焦点（如 `tab` 间 `ArrowLeft/Right`），`Home/End` 跳首尾。
- 仅一个子项在任一时刻可聚焦。

### 3. SPA 路由切换
- 切换后把焦点移到新页面的主标题或 `main`（`tabindex="-1"`），让读屏从头播报。
- 不要停留在已卸载的旧元素上。

## 跳转到主内容（Skip Link）

```
<a href="#main" class="skip-link">跳到主内容</a>
<main id="main" tabindex="-1"> ... </main>
```
- skip-link 视觉可隐藏，但聚焦时必须可见；首个 Tab 即可达。

## 高频坑

1. **模态关不掉**：陷阱逻辑漏了 Esc，或背景仍可 Tab 进。
2. **焦点丢给已移除的节点**：关闭后 `.focus()` 到一个已 `display:none` 的元素 → 焦点回到 `<body>`。
3. **`aria-hidden="true"` 内藏可聚焦元素**：视觉隐藏但键盘能进、读屏不读，双重错位。
4. **新内容出现但焦点不动**：错误提示弹出、Tab 切走，用户不知道发生了什么。
5. **滚动未跟随焦点**：动态聚焦的元素在视口外，键盘用户"看不见焦点去哪了"。

## 限制

- 焦点管理必须配合语义/ARIA（见 `semantic-html-aria.md`）：光移焦点、role 不对，读屏仍读错。
- 最终是否"好用"需读屏实测（见 `screen-reader-testing.md`）。
